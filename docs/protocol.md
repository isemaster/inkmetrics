# Протокол: агент на ПК ⇄ прибор (HTTP поверх USB-сети)

Прибор подключается одним USB-кабелем и отдаётся хосту как **составное USB-устройство**:
сетевая карта RNDIS (адрес прибора `192.168.7.1`, хост получает `192.168.7.2` по DHCP) и
диск на 3,69 МБ со скриптами агента. **COM-порта в текущей сборке нет** — всё общение идёт по
HTTP: ни терминала, ни Web Serial, ни консольных команд.

## Агент → прибор: `POST /ingest` (раз в минуту)

Тело — плоский JSON (до 512 байт). **Все поля необязательны**: чего нет, то прибор не
разберёт и покажет прочерк.

| Поле | Смысл |
|---|---|
| `hostname` | имя компьютера |
| `cpu_percent`, `mem_percent`, `disk_percent` | загрузка ЦП, памяти, системного диска, % |
| `cpu_temp` | температура процессора, °C |
| `gpu_count` | сколько видеокарт (0 — нет или старый агент) |
| `gpu0_percent`, `gpu0_temp`, `gpu0_mem_percent` | первая карта: загрузка %, температура °C, память % |
| `gpu1_percent`, `gpu1_temp`, `gpu1_mem_percent` | вторая карта (при нескольких — вторая из списка) |
| `ping_ok`, `ping_ms` | доступен ли интернет у хоста и за сколько мс |
| `ping_target` | узел, который агент проверял (обычно с прибора) |
| `uptime_hours`, `tcp_established` | аптайм ПК и число TCP-соединений |
| `smart_status` | состояние диска: `OK` / `WARNING` / `UNHEALTHY` |
| `timestamp` | время замера в формате ISO |

Данные считаются свежими `INGEST_STALE_S` = 90 с (агент шлёт раз в 60 с). Дольше — прибор
считает связь потерянной: рамка `OFFLINE`, метрики в прочерки, в `/api/state` поле
`ingest.fresh = 0`.

## Прибор → браузер: `GET /api/state` (JSON)

Верхний уровень: `fw` (версия), `up`, `heap`, `link`, `net_mode`, `ip`, `mode_ru`,
`ping_target`, `ping_ok`, `ping_ms`, `ping_got`, `disk_kb`, `wlock`, `rotation`, `slot1`,
`slot2`, `silence_s`, `fallback_left_s`, `http`, `sensor` (`ok`, `t`, `rh`), `time`.

Метрики хоста — во вложенном объекте `ingest`:

```
"ingest":{"have":1,"fresh":1,"age":4,"count":812,"host":"PC",
          "cpu":8,"mem":41,"disk":63,"gpu_count":2,
          "gpu0":30,"gpu0_temp":62,"gpu0_mem":41,
          "gpu1":95,"gpu1_temp":78,"gpu1_mem":88,
          "cpu_temp":55,"ping_known":1,"ping_ok":1,"ping_ms":16,"ping_got":4,
          "ping_target":"YA.RU","up_h":12.5,"tcp":180,"smart":"OK"}
```

`have` — данные приходили хоть раз, `fresh` — возраст не больше 90 с, `age` — сколько секунд
назад был последний приём, `count` — сколько приёмов всего.

## Страницы прибора

| Адрес | Что делает |
|---|---|
| `/` | сводная страница: то же, что на экране прибора |
| `/setup` | настройки: поворот панели, узел пинга, два крупных числа (слоты), страница прибора |
| `POST /api/settings` | сохранить настройки из `/setup` |
| `GET /api/host-time?unix=<сек>&tz=<мин>` | хост отдаёт приводу своё время (для часов и логов) |
| `GET /api/renew` | попросить адрес по DHCP заново |
| `GET /api/boot` | уйти в режим загрузчика — перепрошивка без кнопки `BOOT` |

## Кнопки и журнал

Кнопки `BOOT`/`PWR` на плате прибор обрабатывает сам (сброс, переключение страницы); их
события видны в `/api/state` и в журнале `idf/README.md` → «чёрный ящик».

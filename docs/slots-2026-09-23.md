# Крупные числа сводного экрана: что выбирается и откуда берётся

> Сделано 23.09.2026, прошивка **0.6.0-idf**, агент метрик — тот же набор полей плюс
> второй источник загрузки GPU. Решение пользователя этой сессии: «на разных ПК доступны
> разные данные — пусть пользователь выберет, что стоит в двух крупных числах».

## Зачем

Раньше крупным шрифтом на сводном экране показывались **температуры двух видеокарт**, и
это была жёсткая привязка к железу:

* температуры карт есть только там, где установлен драйвер NVIDIA (`nvidia-smi`);
* температуры процессора в Windows вообще нет штатным способом (проверено 23.09 на ASUS
  B150-PLUS + i7-7700: `MSAcpi_ThermalZoneTemperature` отдаёт две замороженные зоны
  27,9 / 29,9 °C — они не двигаются при 80 % нагрузки, `Win32_TemperatureProbe` пуст,
  а реальное число читается только драйверным читателем вроде LibreHardwareMonitor,
  который пользователь решил не ставить);

Значит на чужом ПК прибор показывал бы два прочерка в самом крупном месте. Вместо
угадывания набор отдан пользователю: два слота, каждый выбирается на странице настроек
прибора (`/setup`, они же видны и правятся с любого браузера, включая телефон, если прибор
в сети).

## Что нового

| Где | Что |
|---|---|
| `settings.h` / `settings.c` | два поля `slot[0]`, `slot[1]` в NVS (ключи `slot1`, `slot2`), список вариантов — `slot_kind_t`, подписи — `settings_slot_name()` |
| `/setup` (веб) | два выпадающих списка: «Крупное число слева» и «Крупное число справа» |
| экран SETUP | новая строка `SHOW` — какие две величины стоят в крупных числах (подписи те же, что на сводном экране) |
| `/api/state` | поля `slot1`, `slot2` (номера вариантов) |
| `screen.c` | вывод выбранного: подпись над числом из того же выбора, значение — крупным или средним шрифтом (см. ниже) |
| агент `agent.ps1` | загрузка GPU берётся из `nvidia-smi`, а если его нет — из системных счётчиков `GPU Engine` (любой вендор) |

Варианты (номер = то, что лежит в NVS, порядок менять нельзя):

| № | Что | Как считается |
|---|---|---|
| 0 | пусто | слот не рисуется |
| 1 | `CPU %` | проценты от агента (по приросту времени простоя системы) |
| 2 | `RAM %` | занятая память / всего |
| 3 | `DISK %` | занятое место на `C:` |
| 4 | `GPU0 %` | загрузка карты 0 |
| 5 | `GPU1 %` | загрузка карты 1 |
| 6 | `GPU: вторая, иначе первая` | вторая карта, если она есть, иначе первая — так вторая цифра не пустует на однокарточной машине |
| 7 | `GPU0 °C` | температура карты 0 |
| 8 | `GPU1 °C` | температура карты 1 |

**Умолчания:** слева `CPU %` (есть на любом ПК), справа `GPU: вторая, иначе первая`.
Температуры остались в списке — для машин, где `nvidia-smi` установлен.

## Загрузка GPU без NVIDIA: счётчики «как в диспетчере задач»

Диспетчер задач берёт загрузку GPU из счётчиков WDDM `\GPU Engine(*)\Utilization Percentage`
(Windows 10 1709+, любой вендор). Проверено на этой машине: набор есть и отдаёт значения по
каждому процессу и типу движка, например `pid_1284_luid_0x00000000_0x0000a797_phys_0_eng_0_engtype_3d`.

Агент считает так же, как диспетчер: внутри одного типа движка суммирует занятость всех
процессов, затем берёт самый занятый движок (ограничение 100 %). **Разбивка по адаптерам** —
по `luid` в имени экземпляра, то есть вторая карта действительно отдельная:

| LUID на этой машине | Движки | Видеопамять | Кто это |
|---|---|---|---|
| `…aad0` | security, 3d, copy, cuda, videodecode, videoencode | 14 930 МБ | Tesla V100 (сходится с `nvidia-smi`: 14 925 MiB) |
| `…a797` | legacyoverlay, 3d, copy, videodecode, videoprocessing | 0 | Intel HD 530 (на нём рабочий стол) |
| `…aaab` | 3d | 0 | служебный адаптер |

Порядок карт — по видеопамяти (`GPU Adapter Memory`), поэтому карта 0 — дискретная, карта 1 —
встроенная. Температур и процентов памяти этим путём не получить: агент их не отправляет,
прибор показывает прочерк (не ноль).

## Почему крупным шрифтом можно только два знака

Клетка крупного шрифта — 36 px на знак (`FONT_HUGE_W`). Значит:

* `78°` = 2 знака по 36 px + «°» средним шрифтом (12 px) = **84 px**, две температуры —
  168 px из 200 доступных. Так и было;
* `100%` = 3 знака по 36 px + «%» (16 px) = **124 px**, два таких числа — **248 px**.
  Не влезает. Даже без значка: `100` + `100` = 216 px > 200.

Поэтому правило: **если оба числа в строке не длиннее двух знаков — рисуем крупным шрифтом,
иначе оба идут средним** (`18×30`: `100%` = 72 px, два = 144 px). Высота блока при этом не
меняется — средние числа по вертикали встают в то же место, раскладка не прыгает, когда
загрузка доходит до сотни. Стенд предпросмотра это подтверждает: кадр `wide.pgm`.

## Попутно исправлено: числа в строке CPU/RAM/DISK

Три колонки по 66,7 px, а `100%` средним шрифтом — 4 знака по 18 px = **72 px**, то есть на
5 px шире колонки. Числа центрируются по колонке, поэтому два соседних трёхзначных значения
(например `CPU 100%` и `DISK 100%`) накладывались друг на друга на 5 px — то есть читались
одним числом. На живом экране это не всплывало, потому что до сотни доходит редко.

Теперь при трёхзначном значении вся строка идёт крупным шрифтом (`12×22`, `100%` = 48 px при
колонке 66,7 px), замер стенда — кадр `wide.pgm`: между колонками 22–23 px.

## Грабли этой сессии

* **`GET /api/boot` уводит прибор в загрузчик** — работает (проверено 23.09 на 0.5.0 и
  0.6.0). В прежних записях стояло «не уводит, прибор возвращается в приложение» — это
  было неверно; заливка прошивки и диска теперь не требует кнопки BOOT.
* **После сессии esptool порт прибора пропадает на секунду** и появляется снова
  (перечисление USB-Serial/JTAG). Скрипт, который делает несколько вызовов подряд на одном
  и том же имени порта, падает на втором: порт нужно ждать заново. Отсюда «A fatal error
  occurred: Could not open COM5» сразу после успешного `chip_id`.
* **`tools/flash_msc_image.py` зовёт `esptool` из PATH** — в окружении этого ПК его там нет
  (esptool есть у `py -3` и у питона IDF). Заливка диска делается напрямую:
  `esptool --chip esp32s3 --port COMx --baud 921600 --before no_reset write_flash 0x430000
  firmware/media/setup-disk-big.img`.
* **«Липкий» RTC-бит** после `/api/boot` прибор снимает сам при старте приложения
  (`main.c`, `REG_WRITE(RTC_CNTL_OPTION1_REG, 0)`) — отдельно чистить не надо.

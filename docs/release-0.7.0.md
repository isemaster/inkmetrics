# Сборка 0.7.0-idf: проект переименован — `inkmetrics` → `inkmetrics`

> Собрано, залито и опубликовано 23.09.2026. Версия прошивки: **0.7.0-idf**.
> Репозиторий: <https://github.com/advogr2022-max/inkmetrics> (коммит `092d80a`, тег `v0.7.0`).

## Почему переименовали

Имя `inkmetrics` на GitHub уже занято чужими репозиториями (`ink19/InkMonitor`,
`trigg404/inkmetrics` и ещё четыре) — свой репозиторий под этим именем заводится, но в поиске
он не первый и путается с чужими. Пользователь выбрал **`inkmetrics`**: коротко, свободно на
GitHub начисто (0 совпадений), и говорит ровно то, чем прибор стал — метрики на электронных
чернилах.

## Переезд без потерь (это главное, что легко сломать)

1. **Настройки прибора.** Имя набора в NVS сменилось, поэтому в `settings.c` добавлен переезд:
   если в новом наборе (`inkcfg`) пусто, значения (`rotation`, `wlock`, `ping_target`, `slot1`,
   `slot2`) читаются из прежнего (`inkcfg`) и переносятся. Срабатывает один раз — при первой
   загрузке прошивки с новым именем. Проверено: после заливки на приборе остались
   **слоты `1 7`, поворот 90, узел `YA.RU`** — то есть прежние значения, а не умолчания.
2. **Агент на ПК.** Старый агент — не задача-одноразовка, а процесс с вечным циклом
   (`while ($true)`), поэтому мало было переименовать задачу: установщик сначала
   **останавливает процесс прежнего агента по командной строке**, затем удаляет задачу
   `inkmetrics agent`, удаляет папку `C:\ProgramData\inkmetrics` и только потом ставит новый
   агент. Иначе каждый замер уходил бы на прибор дважды. Проверено: папки `inkmetrics` больше
   нет, работающий процесс агента **один**, задача `inkmetrics agent` — `registered (Ready)`.
3. **Деинсталлятор** (`deinstall.cmd`) теперь снимает и старые имена задач, и прежнюю папку —
   машину, где осталась старая установка, убирает одним запуском.

## Что осталось со старым именем осознанно

| Где | Почему |

| константа `NVS_NS_OLD "inkcfg"` в `settings.c` | она и есть механизм переезда настроек — без неё настройки теряются |
| исторические документы (`docs/release-0.5.0…0.6.3`, `docs/screens-v2/v3/v5`, `docs/bugs-2026-09-17.md`, комментарий в `msc.c`) | описывают то, что было на самом деле; переписывать историю — врать в отчётах |
| старые архивы `flash-kit-inkmetrics-*.zip` в корне проекта | это прежние выпуски, они не в репозитории; убираются по слову |

## Папка проекта тоже переименована

Рабочая папка была `D:\inkmetrics` (копия прежнего `D:\inkmetrics` — её не трогали). 23.09 по
просьбе пользователя проект перенесён в **`D:\inkmetrics`**: `mv D:\inkmetrics D:\inkmetrics`,
после чего в 15 файлах проекта (README, ISSUES, NEXT-SESSION, `idf/README.md`, документация) и в
двух скриптах заливки пути переписаны на новый. Переезд самой папки на файлы не влияет — git
хранит относительные пути, репозиторий остался тем же (`092d80a`).

## Замечания

1. **Windows пересоздаёт устройство.** Строки USB и имя диска изменились, поэтому Windows
   заводит прибор как новое устройство (адаптер остаётся тем же — `Ethernet 4`, `192.168.7.2`).
   Если в системе остались «мёртвые» записи прежнего имени, помогает `pc-setup/FIXDISK.PS1`
   (ищет и старое, и новое имя).
2. **README.md в корне — дореформенный**: описывает раннюю схему с хостовым питоновским
   инструментом (`host/`), тогда как сейчас ПК-сторона — PowerShell-агент из `agent-kit/`.
   Для публичного репозитория его стоит переписать; без спроса не трогал.
3. **Папка `pc-setup/`** — легаси-копия комплекта (живёт в `tools/pc_setup/` и `agent-kit/`).
   Имя внутри переименовано, но сама папка осталась как есть.

# inkmetrics

Информационный экран на Waveshare **ESP32-S3-ePaper-1.54** (200×200), подключённый
к ПК по USB. Хост-агент собирает данные (температуры железа, баланс DeepSeek,
ОЗУ/диски, локальные сервисы), рисует кадр и отправляет его на плату.
Кнопки платы настраиваются в браузере.

> Передаёшь работу в новую сессию — сначала `NEXT-SESSION.md` (состояние, первое действие,
> открытые вопросы), затем `MEMORY.md` и `ISSUES.md`.

## ESP-IDF: USB-сеть и сервер внутри прибора (проект `idf/`)

Отдельная прошивка (не Arduino): прибор представляется хосту сетевой картой, выдаёт
адрес по DHCP и отдаёт веб-страницу — на хосте не нужно ставить вообще ничего.

| Что | Значение |
|---|---|
| Адрес прибора | `192.168.7.1` (страница `http://192.168.7.1/`, состояние `/api/state`) |
| Адрес хоста | выдаёт DHCP самого прибора (обычно `192.168.7.2`); можно вместо этого поставить статический адрес без шлюза — см. `tools/fix_usb_net.ps1` |
| Режим USB-сети | **ECM/RNDIS** (NCM Windows не приняла: `CM_PROB_FAILED_INSTALL`) |
| Метрики хоста | агент на ПК (`tools/pc_setup/metrics_agent.ps1`) шлёт JSON на `POST /ingest` раз в минуту; на экране страница 5/5 `HOST SYS`, в `/api/state` — объект `ingest`; разбор и грабли — `docs/ingest-2026-09-17.md` |
| Диск хоста | образ (MBR + FAT16, 7552 сектора) собирает `tools/make_setup_disk.py`, в раздел `msc` пишет `tools/flash_msc_image.py`; файлы можно класть и прямо на том `E:`. **Размер диска должен быть заметно больше дискеты** — 2880 секторов (1,44 МБ) заставляли Windows вешать драйвер гибких дисков (буква `A:`, «Дискета») |
| Сборка | `python C:/esp/idf_build.py -C D:/inkmetrics/idf build` |
| Прошивка | `python tools/flash_ingest.py` (сам находит порт ROM, пишет четыре файла, проверяет по HTTP) |
| Прошивка с другого ПК | `flash-kit/idf/flash.bat COMx` — образы и инструкция в `flash-kit/README.md` и `flash-kit/idf/START-HERE.txt` |
| Логи прошивки | консоли нет; логи идут в «чёрный ящик» (раздел `diag`) — читать `python tools/idf_diag.py` |
| Уйти в загрузчик | зажать `BOOT` при подключении USB, держать ~2 с (`GET /api/boot` в загрузчик не уводит — проверено) |
| Выйти из загрузчика | после заливки чип остаётся в загрузчике: `esptool --chip esp32s3 --port COMx --before no_reset --after watchdog_reset chip_id` (сброс сторожем), иначе передёрнуть USB: `--after hard_reset` на USB-CDC не работает |
| Что осталось и что сломано | `ISSUES.md` (все замечания), `idf/README.md` (порядок работы и грабли) |

Особенности окружения (Windows + git-bash):

- `idf_tools.py`/`idf.py` падают при наличии `MSYSTEM` в окружении — обёртки
  `C:/esp/idf_run.py` и `C:/esp/idf_build.py` его убирают (и заодно снимают SOCKS-прокси,
  без чего pip отказывается работать).
- Тулчейны скачаны через VPS `84.21.191.180` (github release-assets и зеркало Espressif
  отдают нам 0 байт): `python tools/idf_get_tools.py`, установка из локального
  `C:/esp/dist/tools_local.json`.
- Раскладка разделов своя (`idf/partitions.csv`): `app0`/`app1` под OTA (слоты по 3 МБ и
  1 МБ — приложение занимает 0x98000), диск хоста `msc` — **3,69 МБ** (0x430000, 7552
  сектора; раньше было 1,44 МБ, см. ниже про «дискету»), рядом `diag` (логи прошивки) и
  `coredump`. Размер образа диска обязан совпадать с `MSC_SECTORS` в `idf/main/msc.c` и с
  размером раздела — иначе прибор отдаёт хосту не то, что лежит на диске.

## Быстрый старт

```bash
# 1) запустить агент (настроить данные и кнопки в браузере)
cd D:\inkmetrics\host
C:\Python314\python.exe inkmetrics.py
#   -> веб-UI: http://127.0.0.1:8787

# без платы (только предпросмотр кадра):
C:\Python314\python.exe inkmetrics.py --mock

# один кадр в PNG:
C:\Python314\python.exe inkmetrics.py --once preview.png
```

```bash
# 2) прошить плату (сначала бэкап старой прошивки!)
cd D:\inkmetrics
bash tools/flash.sh            # бэкап в firmware/backup + запись inkmetrics
bash tools/build.sh            # только собрать
```

## Веб-доступ по USB (работает сейчас)

1. Подключи прибор — на хосте появляется съёмный диск **1,44 МБ** (например `E:`).
2. Открой файл `INKMETRICS.HTM` **в Chrome или Edge** (Firefox и Safari не умеют Web Serial).
3. Нажми «Подключить прибор» и выбери в списке COM-порт прибора.
4. Дальше страница показывает состояние прибора (прошивка, T/RH, аптайм, память),
   позволяет слать команды (`PING`, `STAT`, `TEST`, `CLR`, инверсия, перезагрузка)
   и **рисовать кадр для панели прямо в браузере** — кнопка «Показать на приборе».

На хосте при этом не устанавливается ничего: прибор сам отдаёт и диск, и страницу,
а общение идёт через Web Serial тем же портом, которым пользуется прошивка.

**Диск не только для чтения:** на прибор можно копировать файлы (конфиг, логи, свои
страницы) — они лежат в отдельном разделе флеша и переживают перезагрузку и
перепрошивку приложения. Служебные команды: `MSCINFO` (сколько занято, сколько файлов),
`MSCFMT` (переформатировать: файлы хоста стираются, страница возвращается).

Размер диска выбран как у дискеты (2880 секторов, 1,44 МБ) осознанно: том без таблицы
разделов Windows монтирует только до этого размера.

> **Важно для IDF-сборки:** этот же размер сыграл злую шутку — Windows приняла прибор за
> дисковод гибких дисков (`USBSTOR\SFloppy…`, буква `A:`, «Дискета»), потому что 2880×512 =
> ровно геометрия дискеты, а для устройства прямого доступа Windows выбирает `Disk` **или**
> `SFloppy`. Там диск увеличен до 3,69 МБ и лежит с MBR + FAT16; разбор —
> `docs/ingest-2026-09-17.md`, пункт З-38 в `ISSUES.md`. Если будете менять диск в
> Arduino-версии — берите размер не 2880 секторов.

**Прошивка прибора идёт через команду `DFU`** (в OTG-режиме порт загрузчика появляется
только так): `bash tools/flash.sh` сам отправляет `DFU`, ждёт порт загрузчика и пишет
прошивку. Ручной путь, если автоматика не сработала: зажать `BOOT` и передёрнуть USB,
затем повторить `flash.sh`.


| Файл | Назначение |
|---|---|
| `firmware/inkmetrics/` | прошивка: драйвер панели, SHTC3, кнопки, протокол |
| `host/inkmetrics.py` | агент: связь, метрики, рендер, веб-UI |
| `host/web/` | веб-интерфейс настройки |
| `docs/pins.md` | распиновка (проверена по примерам Waveshare) |

## Веб-UI (127.0.0.1:8787)

- предпросмотр кадра (как будет выглядеть экран) и кнопки «обновить/страница/TEST/CLR»;
- таблица текущих данных (CPU, GPU, ОЗУ, DeepSeek, llama-server);
- страницы экрана: какие виджеты показывать (checkbox-список);
- привязка жестов кнопок BOOT/PWR: коротко/долго/очень долго → любое действие;
- интервал автообновления, автосмена страниц, нижняя строка;
- журнал и консоль команд плате (`PING`, `STAT`, `ENV?`, `TEST`, `CLR`).

## Ограничения, о которых стоит знать

- **Температура CPU** на Windows без драйвера недоступна. Агент покажет её,
  если запущен LibreHardwareMonitor; иначе — `n/a`. GPU-температуры есть всегда (nvidia-smi).
- Полная перерисовка e-paper ≈ 2 с, поэтому обновление по умолчанию раз в 60 с.
  Частичное обновление — в планах (Ф6).
- Плата должна быть подключена: если COM-порта нет, агент работает в режиме
  предпросмотра и пишет об этом в журнал.
